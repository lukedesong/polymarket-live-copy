# Polymarket 实时跟单系统

## 这是什么

这是一个面向 Polymarket 的实时跟单执行系统。

它的职责很直接：源钱包买入时，按已配置的比例跟买；源钱包卖出时，只卖出本系统此前跟单形成的对应库存。系统持续处理源钱包之后出现的新动作，并把每一步留下可核对的执行记录。

它不是选钱包、预测市场或证明源钱包一定赚钱的研究工具。研究负责决定“跟谁”；本系统负责把已经确认要跟的动作尽可能完整、可靠地执行出来。

## 目标

系统的第一目标是动作完整度：

- 源钱包买，我方跟买。
- 源钱包卖，我方跟卖。
- 不重复下单，不漏记处理结果。
- 在市场、余额、库存或交易所约束导致无法完成时，明确记录原因，而不是静默丢掉动作。
- 任何改动都不能让原本能跟上的动作变成跟不上。

## 工作方式

每个新源动作会经过以下链路：

1. 发现并识别源钱包的新 BUY 或 SELL。
2. 用唯一动作标识去重，并保存前向游标，避免重启后重复处理历史。
3. 读取官方市场信息和当前可执行约束。
4. 按固定跟单比例计算我方目标数量。
5. 检查我方可用现金、对应库存和共享钱包占用。
6. 提交或记录对应跟单决策，并以官方订单、成交和链上结果核对。
7. 将结果写入不可变动作回执和本地账本。
8. 持续监控服务心跳、游标、未决提交和异常，并在需要时告警。

## 核心安全原则

- 只跟启动水位之后的新动作，不追补历史漏单。
- 提交结果不确定时，不重复下单；先保留并核对官方结果。
- 卖出只能使用本系统跟单获得的库存，不能误卖其他持仓。
- 资金、成交、费用和结算以官方账户、官方订单和链上回执为准。
- 多个跟单策略共用同一账户时，统一协调现金、订单提交与结算，避免相互抢占或重复处理。
- 真实订单不会因历史设置或 README 自动启用；每次都需要新的明确授权和即时核验。
- 发布新版本必须经过可验证的发布流程；服务器当前版本由权威版本文件确认，不以目录名或口头记录为准。

## 仓库结构

- `app/`：源动作发现、跟单执行、库存与账本处理。
- `systemd/`：持续运行的服务、健康检查和定时任务。
- `tools/`：发布、版本校验和运行核验工具。
- `ops/`：告警与服务器日常维护脚本。
- `tests/`：防止重复下单、漏动作、误卖库存和账本错误的回归测试。

## 复查与复制

GitHub `main` 是这套系统代码和部署定义的复查入口。服务器的 `current` 发布目录是正在运行的实际版本；每次验证后的服务器发布同步到 `main` 后，两者应保持一致。

仓库只保存可复制的系统代码和部署定义，不保存运行中的状态数据或机器专属配置。
