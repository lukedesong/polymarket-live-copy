# 新钱包筛选标准

按这一份从名单/主页/CSV 里找源。**目标不是找出「表上很赚」的钱包，而是找出形态接近现网 Zockdo / wallet9506、下一步只差延迟盘口测算和用户点名就能考虑接入的源。**

对用户只说实盘跟单。本文件通过 `NEAR_LIVE_COPY` 只表示「接近可跟」，**不是**下单授权，也不是改 `POLYMARKET_LIVE_TRADING`。未点名不得接入现网执行器。

数字来源必须点名：实证值 / 公式推导值 / 外部约束值 / 用户指定值 / 本轮推导值。本轮推导值来自 2026-08-17 稳涨 CSV 86 地址官方重算，**不是最优**，只是能把「能跟的稳」和「表上很稳」切开；以后用现网源再校准，只改阈值不改顺序。

顺序不许跳：**官方账 → 覆盖 → 源稳定 → 袖套 → 复制节奏 → 资金。** 前一步失败就停，给一个标签。

这两个是**稳定形态样本**，不是「必须做天气/网球」。新源要接近的是：周月已结算都赚、事件够、不是一笔撑起来、近阶段没翻亏、仓位没在偷吃利润、成交偏单向、间隔以分钟计而不是十几秒对倒。

## 1. 什么永远不是账

下面任何一项都不能当盈亏或「适合跟」的证据：

- CSV：稳涨、近一周盈利、月度盈利、历史盈利、全程线性 r2、回撤占利润、月榜、成交间隔中位秒
- 排行榜 `DAY` / `WEEK` / `MONTH` / `ALL` 的 pnl、vol、rank
- polymarket.com 活动页、胜率条、页面曲线

反例：`mishipolis` CSV 近一周 +396.55，排行榜 WEEK +457.90，官方上周已结算 **−10139.68 / 264 事件**。

权威只读官方 Data API（本机直连，不经香港）：

| 用途 | 端点 |
| --- | --- |
| 已结算 | `GET https://data-api.polymarket.com/closed-positions?user={addr}&limit=50&offset={n}&sortBy=TIMESTAMP&sortDirection=DESC` |
| 未平仓+残仓 | `GET https://data-api.polymarket.com/positions?user={addr}&sizeThreshold=0&includeArchived=true&limit=50&offset={n}` |
| 仓位价值 | `GET https://data-api.polymarket.com/value?user={addr}` |
| 成交节奏 | `GET https://data-api.polymarket.com/trades?user={addr}&takerOnly=false&limit=100&offset={n}` |
| 用户名→地址 | `GET https://data-api.polymarket.com/v1/leaderboard?userName={name}&timePeriod=ALL&limit=5` 取 `proxyWallet` |

本机 follower SQLite、香港 `/opt/polymarket-live` 库，都不是源盈亏权威。User-Agent 自报，429/5xx 退避重试。

用户名链接（`/@xxx`）先解析成 `0x`，再筛。解析失败 → `DISCOVERY_ONLY`。

## 2. 覆盖（没做完不许往下）

每个地址先写 coverage：

- closed 最早/最晚 UTC、行数、是否截断（翻到空页或 cap）
- positions 行数、是否含 archived、零价值 redeemable 行数
- trades 样本笔数（节奏至少 200 笔；不足则写实际 n 和跨度小时）
- 月窗口独立事件是否 `n=0`

统计单位分开：fill 行 ≠ 事件 ≠ 仓位行。事件键=`eventSlug`，缺则 `slug`，再缺 `conditionId`。

分页：`limit=50`，`offset` 加 50 直到本页 `<50`。closed 从新到旧，整页最老时间早于「上上个日历月月初」可停。仓位 cap 建议 2000 行；打到 cap 仍有下一页 → 截断，未平仓数字标 `pos_trunc=true`，不得装成完整。

**月窗口事件 n=0**（截断或账户从月中才有 closed）：不得报「月通过」。结论最多 `DISCOVERY_ONLY` 或 `REJECT_SOURCE`。

---

## 3. 四个时间窗口（每次都算）

用探测时刻的 UTC。`weekday()`：周一=0。

| 窗口 | 起 | 止（不含，除非写含今天） |
| --- | --- | --- |
| 最近完整 UTC 周 | 本周一 00:00 再减 7 天 | 本周一 00:00 |
| 最近完整 UTC 月 | 上月 1 日 00:00 | 本月 1 日 00:00 |
| 近 3 个日历日 | 今天 00:00 减 3 天 | 现在（含） |
| 当前未完成 UTC 周 | 本周一 00:00 | 现在（含） |

closed 行的 `timestamp`：若 `>1e12` 先除 1000，再当 Unix 秒。只把 `start <= ts < end`（近 3 日和本周用 `<= now`）的行计入该窗口。

---

## 4. 公式（必须可复算）

对窗口内每行：

```
event = eventSlug 或 slug 或 conditionId
pnl  += realizedPnl
cost += totalBought * avgPrice
```

同一 `event` 合成一条。然后：

```
N            = 独立 event 数
wins/losses  = pnl>0 / pnl<0 的 event 数
Σpnl         = 各 event pnl 之和
max_win      = 正 pnl event 的最大值（没有则为 0）
without_max  = Σpnl - max_win
max_share    = max_win / 所有正 pnl 之和     （正 pnl 合计为 0 则空）
poc          = Σpnl / cost                   （cost=0 则空）
```

未平仓（positions 每一行 `size>0`）：

```
mark_pnl = currentValue - avgPrice*size     （无 currentValue 则用 curPrice*size）
cashPnl  = 接口 cashPnl 字段求和（优先报告这个）
redeem0  = redeemable 且 (currentValue=0 或 curPrice=0) 的行数
```

`redeem0` 计入已结束损失，不要当成「还在赌」。`/value` 是仓位盯市，不是已结算盈亏，必须并列，禁止只报一个。

成交节奏（最近 200 笔，不足则全用）：

```
gap_i        = 相邻成交时间差（秒），按时间排序
gap_median   = 中位数
buy_share    = BUY 笔数 / 总笔数
rev_lt_60    = 同一 asset 上相邻两笔方向相反且间隔 <60 秒的次数
```

## 5. 源稳定闸门（任一失败 = `REJECT_SOURCE`）

过完这些，只证明**源还在赚钱且不是假稳**，还不等于能跟。

1. 周独立事件 `N >= 10`，月 `N >= 10`（本轮推导；现网周 46/165。事件 2–9 只够 `DISCOVERY_ONLY`，不够接近实盘）
2. 周 Σpnl `> 0` 且月 Σpnl `> 0`
3. 周 `without_max > 0` 且月 `without_max > 0`
4. 周 `max_share < 0.30` 且月 `max_share < 0.35`（本轮推导。反例 `MisTKy` 上周 72.7% 来自「美军是否 2027 前打伊朗」）
5. 近 3 日 `N >= 2` 时：Σpnl `>= 0`；若 `<0` 且（`<= -2000` 或 `<= -0.3 × 周Σpnl`）→ 淘汰
6. 近 3 日 `N >= 3` 且 `without_max <= 0` → 淘汰
7. 本周未完 Σpnl `< 0` 且（绝对值 `>= 1000` 或 `<= -0.1 × 周Σpnl`）→ 淘汰。**N=1 也算**（反例 `MisTKy` 本周 −3679.19 / 1 事件）
8. 未平仓 `cashPnl > -2000`，且不得出现：周 Σpnl`>0` 而 `|cashPnl| >= max(2000, 0.20 × 周Σpnl)`  
   反例：`trinity42` 周 +9074 / 未平仓 −179266；`igot50k` 周 +96104 / 未平仓 −618214；`humbleboy` 周 +18909 / 未平仓 −52255
9. 月亏损事件数 / 月 N `< 0.40`（本轮推导。现网 Zockdo 约 26/250=10%，9506 月 0 亏。反例 `Nadmi` 211/326=65% 不得当接近实盘）

过 1–9 → 源侧可进入复制闸门。未过 → 停。不要用「周很赚」覆盖未平仓大亏。

---

## 6. 袖套（过源之后立刻切，切不开就降级）

用**交易前能看见的**标题/eventSlug 分类，禁止先看谁赚钱再把亏的叫乱赌。

至少报最近 200 笔和上周 closed 的占比：天气、网球/体育、电竞、加密、政治/时长盘、其他。

接近实盘还要：

- 单一主袖套占上周事件 **或** 最近 200 笔 **>= 60%**
- 写清生命周期：持有到结算 / 主动 SELL / 篮子多腿 / 对冲。BUY/SELL 只是相对 outcome 的方向，不是 maker/taker
- 现网两个源是偏单向、间隔分钟级。主袖套是「局内电竞对倒、秒级买卖」→ 即使源赚钱也走复制失败，不是接近实盘

切出多个完全不同的玩法时，只允许把通过的那一只袖套当候选，禁止「整个钱包一起跟」。

过源、过袖套，但还没过复制 → `SOURCE_CANDIDATE`（研究用，**不要**当成接近实盘发给用户当可跟）。

## 7. 复制闸门（这决定「接不接近实盘」）

源没过，禁止做复制结论。源过了，用官方 200 笔（不是 CSV 间隔）。

### 7.1 一票否决 = `BLOCK_COPYABILITY`

- `gap_median < 90` 秒（反例 `BettingPartners4` 15 秒，BUY 113 / SELL 87，60 秒内反向 72/140）
- `buy_share < 0.75` 且 `rev_lt_60 >= 20`（局内对倒）

Zock 退赛盘口我们晚约 1 秒也会丢。十几秒级的源，发现后再读盘口，优势已经没了。

### 7.2 接近实盘 `NEAR_LIVE_COPY`（必须全部满足）

本轮推导，对照现网 612 秒 / 2030 秒、BUY 100%：

| 项 | 线 |
| --- | --- |
| `gap_median` | **>= 400 秒** |
| `buy_share` | **>= 0.90** |
| `rev_lt_60` | **<= 2** |
| 主袖套 | 上周或近 200 笔 **>= 60%** 同一可解释类 |
| 源闸门 1–9 | 全过 |
| 延迟盘口测算 | **尚未做**也可以叫 NEAR_LIVE_COPY，但必须在结论里写「未测算，未授权接入」 |

400 秒、90% BUY 不是物理定律；松于现网 9506 的 612 秒/100% BUY，紧于「90 秒就算能跟」。达不到就不要写接近实盘。

`NEAR_LIVE_COPY` 的下一步只有：按源成交时间做延迟后 Ask/Bid/深度/费用/最低量回放，算 intention-to-follow 是否仍为正。**那一步通过之前禁止** `QUALIFIED_FOR_MINIMUM_LIVE_CANARY`，禁止接入。

### 7.3 延迟测算（NEAR 之后才做，本筛不自动做完）

对每个源 BUY/SELL：记录源时间、我方首次可见、当时可执行价、深度、费用、最低量、能成交量、跳过原因。SELL 只能映射我方已有跟单库存。篮子缺腿=该事件复制失败。没有这组数，不得说「可以实盘」。

## 8. 资金（只对 `NEAR_LIVE_COPY`）

分开五笔，禁止用累计买入额当资金池：

1. 源可观察袖套的历史现金缺口下界（按时间重放买/卖/费/结算/并发仓）
2. 我方拟用固定 share-scale
3. 历史峰值占资 × 该比例
4. 结算前占用 + 运营缓冲
5. 用户指定实盘预算（用户指定值，不是最优）

最低量只决定成交、部分成交或跳过，禁止凑整放大。

## 9. 标签（每个地址恰好一个）

| 标签 | 对用户的意思 | 能不能当「接近可跟」 |
| --- | --- | --- |
| `DISCOVERY_ONLY` | 覆盖没做完 | 否 |
| `REJECT_SOURCE` | 源不稳或假稳 | 否 |
| `SOURCE_CANDIDATE` | 源过了，节奏或袖套还不够像现网 | 否 |
| `BLOCK_COPYABILITY` | 源可能赚，我们跟不上 | 否 |
| `NEAR_LIVE_COPY` | 源+节奏+袖套接近现网两个源；还没做延迟盘口，未授权接入 | **是，这才是按本文要找的** |
| `QUALIFIED_FOR_MINIMUM_LIVE_CANARY` | 延迟盘口也没否决；仍须用户点名才下单 | 是，但本筛到不了这一步 |
| `ALREADY_LIVE` | 已经在跟 | 不进新池 |

只把 `NEAR_LIVE_COPY`（以及之后的 QUALIFIED）当成「找出来接近可以实盘的钱包」。`SOURCE_CANDIDATE` 可以记在附录，不要当推荐跟单。
