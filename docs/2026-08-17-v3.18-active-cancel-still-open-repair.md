## 4. 最小修复

只改两个文件：

- `app/cd90_live_copy.py`
- `tests/test_cd90_live_copy.py`

### 4.1 适配器

`CLOBExecutionAdapter.cancel_active_gtd_order`：官方仍看得到该单时，**不再 raise**，返回：

```python
{
    "active_cancel_response": cancel_response,
    "active_cancel_verified": False,
    "active_cancel_still_open": True,
}
```

此时不读 chain head，不宣称已终局。

### 4.2 维护循环

`cancel_due_active_gtd_orders`：

- 仍兼容旧适配器抛出 `RuntimeError("ACTIVE_CANCEL_ORDER_STILL_OPEN")`
- `active_cancel_verified is not True` 时：
  - 尝试状态保持 `SUBMITTED_UNRECONCILED`
  - `active_cancel_verified=False`
  - `active_cancel_still_open=True`
  - 记 transition `ACTIVE_CANCEL_ORDER_STILL_OPEN` / `GTC_ACTIVE_CANCEL_STILL_OPEN_AFTER_REQUEST`
  - **不**释放 reservation
  - **不**新提交
  - 继续处理下一单，不让异常冒出 head 循环
- 因为 `active_cancel_verified` 仍是 False，下一轮还会再撤

SELL 路径、零成交/全成交提前撤单条件、份额、最低量、CD90 暂停，都没动。
