# BUY 部分成交立即撤单设计

## 目标

当已受理的 BUY `GTC_ACTIVE_CANCEL` 出现官方正数但未完全成交的数量时，不再等待原固定撤单时点，立即撤销旧单；旧单完成官方关闭并由 Polygon finalized order-hash 扫描覆盖撤单后链头后，现有重试器才可按精确剩余份额重新挂单。

## 最小范围

- 只改 BUY GTC 的部分成交触发条件。
- 零成交继续等待现有撤单时点。
- SELL 即时 FAK 不变。
- 动态价格上限、份额比例、最低量、UNKNOWN 不重发和撤单后最终性合同不变。
- 不新增表、服务、参数或人工订单路径。

## 数据流

每个新区块的现有 GTC 维护先读取官方订单。若 `0 < size_matched < requested_quantity`，立即调用现有精确订单撤销入口，并把触发原因与当时官方已成交份额追加到不可变 transition。随后仍由现有 reconciliation 读取官方终态、等待 finalized scan 覆盖撤单后链头、累计权威 fill，并只对精确剩余量开放重试。

## 安全边界

- 新单绝不早于旧单关闭与撤单后 finalized 证明。
- 官方订单读取失败时保持原单和预留，不因推测触发重试。
- 已完全成交的订单不走“部分成交撤单”分支。
- 同一订单的撤单保持幂等，只执行一次。

## 验收

失败测试必须证明未来撤单时点尚未到达时，部分成交仍会立即撤单；同时证明零成交和完整成交不会提前撤单。完整相关回归通过后，使用现有 closed-loop release 发布，唯一修复版本从服务器权威 `3.16` 增至 `3.17`，并即时验证服务、游标、SQLite、活动订单与 UNKNOWN 状态。
