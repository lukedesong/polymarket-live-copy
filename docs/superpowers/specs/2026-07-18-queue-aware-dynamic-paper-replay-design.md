# Polymarket 队列感知动态价格纸面回放设计

Date: 2026-07-18

## 目标

把当前世界杯赛前纸面做市从“触价或穿价即整单成交”升级为一套单一、可复核、尽可能贴近真实盘面的回放模型。新模型必须使用官方订单簿的动态价格、逐笔成交方向和数量，维护排队量与订单剩余量，支持部分成交，并按真实盘口深度计算库存清仓价值和净盈亏。

本阶段仍不提交、修改或撤销任何真实订单。现有 `strict` 与 `touch` 账本保留为历史对照，但不再用于判断策略是否具备真实资金资格。

## 已确认的产品决定

- 输出一套权威纸面结果，不用“乐观/保守”双结果代替判断。
- 价格必须随官方买一、卖一和完整订单簿变化，不得把首次观察到的价格固定到运行结束。
- 纸面成交量必须受官方逐笔成交数量和排队量约束。
- 支持部分成交；不得把一次很小的官方成交放大为整张纸面订单成交。
- 买入后的库存按真实可执行买盘深度估值；风控清仓逐档消耗买盘并计算滑点和费用。
- 不编造撤单发生在纸面订单之前或之后的概率。
- 用户指定的赛前风控边界继续生效；它们是用户指定值，不是已证明最优参数。

## 官方数据与可观测边界

模型只依赖 Polymarket 官方接口：

- Market WebSocket `book`：完整 Level-2 价格档位与聚合数量。
- Market WebSocket `price_change`：新订单或撤单后的价格档位聚合数量，以及最新买一卖一。
- Market WebSocket `last_trade_price`：成交价格、方向、数量、费用字段与服务器时间。
- Market WebSocket `best_bid_ask`：买一、卖一和价差变化。
- User WebSocket：只在将来真实提交订单时，提供本账户订单 ID、累计成交量和订单生命周期。

公开 Market WebSocket 不提供每张外部挂单的订单 ID，因此纯纸面阶段无法知道一次无成交的档位数量减少发生在我方队列之前还是之后。只有真实提交订单并读取私有 User WebSocket，才能观察本账户的真实部分成交。

因此，纸面模型采用唯一的“可观测队列回放”：

- 加入价位时，当前该价位全部公开数量记为我方前排数量。
- 后续同价位新增数量视为在我方之后，不增加前排数量。
- 只有方向、价格均能消耗我方报价的官方成交数量，才减少前排数量。
- 没有对应官方成交的档位数量减少不改变前排数量，因为其队列位置不可观测。
- 该规则不声称还原了未知撤单位置；它是不引入主观撤单概率时唯一可重复计算的纸面口径。

模型使用价格优先和同价位时间顺序进行队列回放。Polymarket 公共文档没有提供公开订单级队列身份，因此该假设必须在将来的真实小额订单校准中验证，不能单独授权扩大真实资金。

## 报价与队列生命周期

### 新报价

在 `PREMATCH_OPEN` 状态，针对每个入选 outcome token：

- 买单加入当前最佳买价，数量继续使用官方市场最小下单量。
- 只有存在非负库存时，卖单才加入当前最佳卖价；不得模拟裸卖空。
- 新订单记录价格、原始数量、剩余数量、当时价位公开数量、前排剩余量、订单簿时间和本地接收时间。

### 价格不变

如果买一或卖一价格没有改变，只是档位聚合数量发生变化：

- 保留原订单，不取消重挂。
- 保留原队列加入时间。
- 官方成交按顺序消耗前排数量。
- 新增公开数量不增加前排数量。
- 不可定位的撤单不减少前排数量。

这修复当前引擎在任意盘口更新时取消并重开订单、从而不断丢失队列位置的问题。

### 价格改变

当前策略仍定义为跟随最新买一和卖一。因此，当参考最佳价格改变时：

- 撤销旧纸面报价，并记录 `best_price_changed` 原因。
- 按新的最佳价格建立新纸面报价。
- 新价格档位的公开数量成为新的前排数量。
- 记录旧价格、新价格、价差和库存清算价值的变化。

如果价格变化使订单簿不完整、交叉或无法解析，停止报价和成交判断并进入数据阻断状态。

## 官方成交与部分成交

`last_trade_price` 的价格、方向和数量全部参与成交判断。运行时必须验证成交方向和价格与当前订单簿状态相容；不相容事件保留原始记录并标记，不能静默生成纸面成交。

对纸面买单：

- 只有主动卖出方向的官方成交才可能消耗买单队列。
- 成交价格等于买单价格时，先消耗前排数量；超出的官方成交量用于部分或全部成交我方订单。
- 成交价格低于买单价格时，说明市场已经穿过我方更优买价；在数据顺序完整、方向相容且订单仍有效时，我方剩余订单按全部成交处理，并标记证明类型为 `TRADE_THROUGH`。此时较低价成交事件的数量是扫过更优价位后的剩余量，不能错误地再次作为我方成交上限。

对纸面卖单采用镜像规则：只有主动买入方向的官方成交可以消耗卖单队列。

同价位排队成交数量为：

```text
min(
  官方成交量扣除可观测前排后的剩余量,
  纸面订单剩余量,
  可卖库存（仅卖单）
)
```

严格穿价成交不使用上述同价位剩余量公式；它依据市场已经越过我方限价这一事实，将仍有效的剩余订单全部成交。每笔成交必须记录 `AT_PRICE_QUEUE` 或 `TRADE_THROUGH` 证明类型，避免混淆两类容量依据。

成交后订单可以保持 `PARTIALLY_FILLED`，直到剩余量为零、价格改变、风控撤单或数据断线。每个官方事件只能按其可用数量消费一次，必须保持幂等。

## 动态价格漂移

价格漂移是新模型的强制组成部分：

- 每次订单簿更新后重新计算买一、卖一、中间价、价差和库存可执行清算价值。
- 每笔买入成交记录成交时买一、卖一和完整买盘深度引用。
- 成交后的每次有效盘口变化都记录相对于成交价的可执行买一漂移和深度清算漂移。
- 不设置未经验证的固定秒数窗口；漂移沿订单生命周期持续记录，直到对应库存卖出或被风控清仓。
- 最终退出漂移以实际纸面卖出价格或强制清仓成交均价为准。

本次既有样本中买一卖一价格保持稳定、数量频繁变化，因此既有触价利润只能代表稳定价格场景。新模型必须能够在未来价格上移、下移、点差扩大和点差收窄时产生不同盈亏。

## 库存估值与强制清仓

库存采用移动加权平均成本，但未实现盈亏不再只使用买一价格乘数量。

### 持续估值

按当前完整买盘从最高价向下逐档模拟卖出库存：

- `liquidatable_quantity`：当前盘口能够承接的库存数量。
- `liquidation_proceeds`：逐档成交后的预计回款。
- `liquidation_vwap`：预计清仓均价。
- `unliquidated_quantity`：盘口深度不足时无法清算的数量。
- `depth_adjusted_unrealized_profit`：清仓回款减库存成本及适用费用。

盘口无法覆盖全部库存时，不得为剩余库存伪造价格；必须单独报告无法清算数量。

### 风控退出

进入用户指定的降仓状态后停止增加库存。进入强制撤单或比赛中阻断状态时：

- 撤销全部纸面挂单。
- 使用当时完整买盘逐档模拟清仓现有库存。
- 每档成交不得超过该档公开数量。
- 费用读取当时官方市场参数；Maker 挂单不预收 Taker 费用，强制吃单清仓按官方 Taker 费用公式计算。
- 深度不足的剩余库存保持未平状态并明确报告，不假定能够结算前退出。

## 净期望与报告口径

单次运行的队列感知净盈亏为：

```text
实际纸面卖出收入
+ 当前深度可清算回款
+ 已实际确认的 Maker 奖励
- 实际纸面买入成本
- 官方 Maker/Taker 费用
- 无法清算库存的已确认损失
```

未确认 Maker 奖励不计入收入。无法清算但尚未产生已确认损失的库存单独列示，不得按零风险处理，也不得伪造为已实现盈亏。

报告至少包含：

- 官方成交事件数与官方成交总量。
- 纸面订单数、部分成交数、完全成交数和撤单数。
- 加权平均前排量、累计被官方成交消耗的前排量。
- 买入成本、卖出收入、官方费用、深度清算价值。
- 已实现盈亏、深度调整未实现盈亏和队列感知总盈亏。
- 成交后可执行价格漂移与最终退出漂移。
- 最大库存、无法清算数量和风控清仓结果。
- 数据异常、方向不相容事件和丢失顺序事件。

Google Sheet 继续保持现有页面结构。新字段优先替换不再作为决策依据的触价摘要；不得创建额外页面，除非用户另行授权。

## 存储变更

在现有 SQLite 事实源中扩展或新增以下逻辑结构：

- `paper_orders`：原始数量、剩余数量、前排初始量、前排剩余量、部分成交状态、重排原因。
- `paper_fills`：部分成交数量、官方成交总量、该事件用于前排的数量、用于我方成交的数量、成交前后剩余量。
- `paper_queue_events`：每次入队、前排消耗、价格变化重排、撤单和数据阻断。
- `paper_inventory_marks`：订单簿事件时的买一、卖一、深度清算数量、清算均价和清算回款。
- `paper_liquidations`：风控清仓逐档结果、费用、未清算数量和原因。

所有货币、价格和数量继续以十进制定点值存储。数据库是唯一事实源，Google Sheet 只是展示层。

## 运行模式与兼容性

- 新增 `queue` 纸面成交模式，作为当前策略判断的权威模式。
- `strict` 和 `touch` 保留为历史研究工具，但状态输出必须标记为 `comparison_only`。
- `paper-export` 增加稳定的队列、部分成交、漂移、深度清算和净盈亏字段。
- 新模式使用独立 SQLite 数据库，避免污染既有两套账本。
- 不加载真实交易凭据，不实例化真实订单提交客户端。

## 错误处理

- WebSocket 断线立即撤销纸面订单；重连取得完整 `book` 前不恢复队列。
- 事件时间倒序、重复或缺失时记录异常并阻止受影响订单成交。
- 成交数量、价格或方向缺失时不生成纸面成交。
- 盘口价格交叉、档位为负或无法解析时进入数据阻断。
- 订单簿与成交方向不相容时保留证据并阻止该事件消费队列。
- 强制清仓深度不足时保留剩余库存，不使用估算价格补齐。

## 测试策略

实现遵循测试驱动开发，每项行为先出现对应失败测试。必须覆盖：

- 新订单以前排公开数量加入队列。
- 同价位数量更新不取消重挂。
- 同价位新增数量不增加前排量。
- 无成交的数量减少不减少前排量。
- 官方成交数量先消耗前排，再部分成交纸面订单。
- 单一官方事件不能超量消费或重复消费。
- 价格变化撤销旧单、建立新单并重置队列。
- 买单和卖单方向匹配及不相容事件阻断。
- 部分成交后剩余订单与库存一致。
- 每次盘口变化更新深度清算价值和价格漂移。
- 多档买盘清仓、费用、滑点和深度不足。
- 风控边界、断线、重连和比赛开始阻断。
- SQLite 迁移兼容既有数据库。
- `paper-export` 与数据库逐笔重算一致。
- 全套回归测试证明没有真实订单调用。

## 数字来源审计

| 数字或参数 | 分类 | 用途 |
|---|---|---|
| 官方成交价格、方向、数量 | 实证值 | 队列消耗和部分成交 |
| 官方订单簿价格与档位数量 | 实证值 | 初始排队、动态报价和深度清算 |
| 官方最小下单量、Tick、费用参数 | 外部约束值 | 订单合法性和费用计算 |
| 赛前风控时间边界 | 用户指定值 | 风控状态机；不声称最优 |
| 价格优先和同价位时间顺序 | 估算值/待校准机制假设 | 纸面队列回放；不能单独授权扩大实盘 |
| 撤单在队列中的位置 | 不可观测 | 不引入概率，不用于减少前排量 |

不新增成交概率、撤单分配比例、漂移时间窗口、盈利阈值、仓位上限或真实订单金额。需要这些数字时必须另行取得实证、外部约束或用户明确指定；估算值不能授权真实订单。

## 验收标准

新模型只有在以下条件全部满足时才算完成：

- 官方逐笔成交数量能够逐笔消耗纸面队列并产生可复核的部分成交。
- 价格不变时订单保持队列；价格改变时订单重排并记录漂移。
- 库存估值和风控清仓逐档使用当时真实订单簿深度。
- 净盈亏能够从逐笔现金流、费用、未平库存和深度清算记录独立重算。
- 回放输出不再机械等于完整触价次数乘固定点差。
- 数据异常和不可观测项被显式报告，不伪造成交。
- 单元测试、集成测试、旧模式回归测试和官方数据短时回放全部通过。
- 新模式运行期间真实订单提交数和真实账户仓位变更均为零。

完成纸面模型不等于策略已证明正期望。进入真实小额校准前，必须用私有 User WebSocket 对真实排队、部分成交和纸面误差进行比较；任何真实订单金额仍需独立的数字依据和用户授权。
